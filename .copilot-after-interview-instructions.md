# Coding-agent / Copilot instructions for After-Interview Report

When editing or extending the after-interview feature, keep these constraints in mind:

- Use the existing pipeline: frontend -> `/api/after-interview/ingest` -> VTT parser -> normalized transcript -> report generator.
- Maintain review-only language: use "review signal" and "evidence packet". Do not implement automated hiring decisions.
- Respect secrets: `GRAPH_ACCESS_TOKEN` must only live in the ignored root `.env`; never expose it to the frontend or commit it.
- The API loads `../../.env` through its workspace development script. Do not add a second `apps/api/.env` configuration source.
- Tests: add small unit tests for `parseVttToTranscript` and `generateMockReport` when adding parsing or signal logic.

Files of interest:
- `apps/api/src/routes/afterInterview.js`
- `apps/api/src/lib/vttParser.js`
- `apps/api/src/lib/reportGenerator.js`
- `apps/api/src/services/graphClient.js`
- `apps/frontend/src/screens/report/AfterInterviewReport.jsx`
- `apps/frontend/src/services/api/afterInterviewService.js`
